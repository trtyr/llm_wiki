### 核对补充（审计之外的新证据）

1. **F3 的实际影响范围比审计表述更严重**：不止"EventSource 失效"——`/docs` 文档页当前在浏览器打开是**下载一个 .json** 而非渲染页面（Content-Type: application/json）。即"给人看的文档页"目前对人是坏的。
2. **F10 的不可达是双重的**：除审计指出的 skills 惰性化短路外，本轮 planner 门的 `skills_enabled = !skills.is_empty()` 恒 false 也把 `shell.exec` 从规划器可用集中移除。**结论不变：修复 skills 相关代码时必须同步收紧该绕过路径，防止解除惰性化时连带引爆。**
3. **审计"没查什么"部分的基线补充**（本机已实测）：`cargo build` 零警告、`cargo test --lib` 382 过/1 预存失败（`fs::allow_absolute_write_paths`，Windows 环境问题，见 git 历史）、E2E 55→58 项全绿。审计发现的 F8/F9 属 E2E 自身断言缺陷，不影响"后端功能在裸 HTTP 层面可用"这一基线结论。
